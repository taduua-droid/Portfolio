Data review without an EDC

A full offline data review cycle for a mock epilepsy trial: 19 edit checks programmed in Python, a discrepancy listing, 20 queries to three sites, an audit trail for every correction, and a re-run that confirms the data is clean.

The review cycle, start to finish

Without an EDC, nothing blocks a bad entry when it’s typed. Every check runs after the fact, and a person reviews every hit before a query goes out.

  1. 1. Run checks25hits from 19 programmed checks on the v1.0 data
  2. 2. Review hits20queries, after merging hits with a shared cause and routing screen failures to listing review
  3. 3. Query and resolve20/20closed, one after a re-query when the first answer didn’t resolve it
  4. 4. Correct and audit21data changes, each logged with old value, new value, who, when, and why
  5. 5. Re-run0new discrepancies on v1.1; the 7 remaining hits were already reviewed and closed

Nineteen edit checks

Each check is tied to a protocol rule. Hard checks flag data that can’t be right; soft checks flag data that might be right but needs a second look.

Demographics

  • DM01Age at consent outside 18 to 70Soft
  • DM02Screening number doesn’t match the siteHard
  • DM03Childbearing potential answered for females onlyHard
  • DM04Birth date before consent; consent not in the futureHard
  • DM05Randomization outside the 8-week baseline, ±2 daysSoft
  • DM06First dose not the morning after randomizationSoft

Seizure diary

  • SZ01Diary flag disagrees with the counts enteredHard
  • SZ02Two records for the same dateHard
  • SZ03Diary date before consent or after the diary was returnedHard
  • SZ04More than 20 seizures of one type in a daySoft
  • SZ05Missing diary daysSoft
  • SZ06Baseline doesn’t meet the seizure-count rule (Inclusion 6)Soft

Adverse events

  • AE01End date before start dateHard
  • AE02Ongoing status, end date, and outcome disagreeBoth
  • AE03Serious flag disagrees with seriousness criteriaHard
  • AE04Started before consentSoft
  • AE05Started before first dose but marked as relatedSoft
  • AE06A seizure recorded as an AE (protocol 10.4.1)Soft
  • AE07Fatal outcome not marked serious with deathHard

Two review listings run alongside the checks: ML01 flags dose reductions in Week 1 or after Week 8, and ML02 lists serious adverse events for reconciliation against the safety database.

Two fixes to the spec, found by testing

Building the test data exposed two places where the data management spec would have produced wrong results.

Anchor baseline on the consent date

The eligibility listing runs before randomization exists, so it counts from Visit 1, the consent date.

Baseline is every day before randomization

A fixed Day −56 breaks when Visit 3 is delayed, because the real baseline is then longer than 56 days.

Four queries, start to close

Most queries end in a simple correction. These four show the cases that take judgment.

QRY-011: a re-query

SZ01, Hard, Site 002
Query
The diary says no data was recorded for this day, but seizure counts are entered.
Site
The subject reported no seizures that day.
Re-query
If there were no seizures, the flag should be Yes with counts of 0. If the diary page is blank, counts should be blank. Which applies?
Site
The diary page is blank. Zeros removed.
Data review
The day is now left out of the seizure-rate denominator instead of counting as seizure-free.
Data corrected13 days to site response

QRY-009: an escalation

SZ06, Soft, Site 003
Query
The diary data shows only 2 qualifying seizures in weeks 1 to 4 of baseline, short of the 3 that Inclusion 6 requires. Please verify against source.
Site
Entries re-verified against the diary. The data are correct.
Data review
Data confirmed and escalated to the CRA and medical monitor as a potential eligibility deviation. Whether the subject continues is the sponsor’s decision, not data review’s.
Escalated5 days to site response

QRY-020: one cause, two checks

SZ03 and SZ05, Site 002
Query

Site
The month was mistyped. Corrected to 11-SEP-2026.

Judgment calls

Decisions a check can’t make on its own.

Blank isn’t zero

A blank diary day and a seizure-free day mean different things. Treating blanks as zeros would make seizures look less frequent, so blank days stay out of the seizure-rate denominator.

One cause, one query

Twice, two checks fired on the same underlying error. Each pair went out as a single query, so the site was never asked the same thing twice.

Data review doesn’t decide eligibility

When correct data showed a possible eligibility deviation, the job was to confirm the data and escalate it, not to rule on whether the subject stays.

  • ICH E6(R3)Data integrity and record keeping
